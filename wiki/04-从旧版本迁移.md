# 04 · 从旧版 SDK 迁移到 v0.12.0

## 核心变更

| 旧版路径 / 命名空间 | 新版 | 处理方式 |
|---|---|---|
| `SDK/Interop/*.cs` | `SDK/Native/Runtime/*.cs` | `Il2CppNative` / `NativeTypedFields` 改到 `AstralParty.Modding.SDK.Native`。|
| `SDK/UI/*.cs` | `SDK/Native/Widgets/*.cs` | `IModUiService`、`UiWatchTarget`、`NativeUiLayout` 等改到 `SDK.Native`。|
| `SDK/Native/Interop/*.cs` | `SDK/Native/Runtime|Assets|Controls|Gameplay/` | 移除 `.Interop` 子命名空间。|
| `SDK/Native/UI/*.cs` | `SDK/Native/Widgets|Controls/` | 移除 `.UI` 子命名空间。|
| `SDK.Native.dll`（v0.10.x） | `AstralParty.Modding.SDK.dll` | v0.11.0 已合并；需要在新版源码下重新编译依赖者。|
| `HeroPreviewOrdering.cs` 等空占位 | 删除 | 类已经由宿主 MOD 实现；SDK 内不再留注释-only `.cs` 文件。|

例如：

```diff
-using AstralParty.Modding.SDK.Native.Interop;
-using AstralParty.Modding.SDK.Native.UI;
+using AstralParty.Modding.SDK.Native;
```

类型所在程序集虽然仍是统一 SDK，但**类型完整名称已改变**，只替换旧 DLL 并不能修复已编译的第三方 MOD；它们必须重新编译。BepInEx 运行目录避免同时存在同名 SDK DLL 的多个版本。

## 已删除的空占位源码

- `Game/HeroPreviewOrdering.cs`
- `Media/PngFiles.cs`
- `Replay/ReplayArchivePolicy.cs`
- `Statistics/AchievementPresentation.cs`

这些文件只含旧功能去向的文字说明，没有声明 SDK 类型。其逻辑仍在 AstralProbe 对应功能包中，不意味着删除 MOD 功能。

## 更新步骤

1. 备份并提交 v0.11.0 当前状态；
2. 通过 Git 增量补丁**或**增量源码包更新其一。使用源码覆盖时务必根据清理清单删除旧文件；
3. 把所有 `using ...Native.Interop/UI` 替换为 `.Native`，也要处理原 SDK 根命名空间的 UI/Interop 类型；
4. 更新项目版本并清空可能过期的 `obj/bin`；
5. 使用当前游戏对应的代理程序集重新编译 SDK、主 MOD 和附属包；
6. 游戏内验证后再发布二进制，确认没有旧 DLL 副本被 BepInEx 扫描。
