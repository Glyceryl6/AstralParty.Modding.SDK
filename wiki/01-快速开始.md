# 01 · 接入和本地构建 SDK

## 环境

- .NET 6 编译目标（项目 `TargetFramework=net6.0`）。
- 能生成并验证 `BepInEx/interop` 的 Windows x64 游戏目录（包含 `Il2Cppmscorlib.dll`、`UnityEngine.CoreModule.dll` 和 `UnityEngine.InputLegacyModule.dll`）。
- 兼容 HybridCLR 的 SNWCreations Il2CppInterop Runtime/Common、IL2CppSharp/Hooking NuGet 依赖。

## 项目引用

```xml
<ItemGroup>
  <ProjectReference Include="..\AstralParty.Modding.SDK\AstralParty.Modding.SDK.csproj" />
</ItemGroup>
```

消费者如直接使用 Unity/游戏代理类型，仍需在自己项目中**独立声明**相同的 `BepInEx/interop` 引用；项目引用 SDK 并不会可靠地把游戏 DLL 自动变成消费者自己的编译引用。

```powershell
$game='D:\Games\Astral Party'
dotnet build .\AstralParty.Modding.SDK.csproj -c Release `
  -p:AstralInteropDir="$game\BepInEx\interop"
```

SDK 根项目统一编译 `Native/**/*.cs`，输出 `AstralParty.Modding.SDK.dll`。没有独立的 `SDK.Native.dll`；引用 SDK v0.11.0/更早版本的旧类型名，先按 [迁移指南](04-从旧版本迁移.md) 修改。

### 本机配置而不是硬编码路径

SDK 单独打开时把 `SdkLocal.props.example` 复制为 `SdkLocal.props`，填写游戏目录。仓库 `.gitignore` 排除此文件；CI 可通过 `-p:AstralInteropDir=...`。不要上传游戏代理 DLL、热更 DLL 或你的本机目录。
